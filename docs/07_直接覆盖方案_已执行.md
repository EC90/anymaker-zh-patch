# 直接覆盖方案（已执行）：en 列 := 官方 zh

**决策**：2026-09-22 用户拍板，推倒 [06_启用官方中文路径论证.md](06_启用官方中文路径论证.md) 的 T1–T4 路线（启动参数/Steam 配置/荷兰语），改为**备份后直接用官方简中覆盖游戏当前显示文本**。本文件是运行手册：原理、已执行记录、还原手段、更新随动流程。

## 1. 原理

- 游戏以英文运行，屏显全部取 `en` 列（en 同时是 `localization.get_english` 的回退源，覆盖后两路都是中文，行为一致）。
- 覆盖规则：**逐行"zh 非空则 en:=zh"**——不整文件替换、不依赖 buildid，官方 1953 个有中文的行全部生效，12 个 en==zh 技术缩写行天然不变，3 个双空行不动。
- **字体必换**：英文语言走 `noto_sans_regular.ttf`（646KB 拉丁字形，无 CJK）→ 覆盖为 `noto_sans_sc_regular.ttf`（含拉丁+简中，英文数字照常渲染）。字体按语言枚举选择（`get_script_font(e_localization_language)` 符号），改文本不改字体必出豆腐块。

## 3. 还原手段（三级）

1. **同版本还原**：`python 工具\zh_overwrite.py restore`——按当前 buildid 从 `备份\rom_b<buildid>\` 还原 5 TSV + 字体。
2. **跨版本/备份丢失**：Steam 库 → 右键 Anymaker → 属性 → 已安装文件 → **验证文件完整性**（官方还原，对任何 buildid 都有效）。
3. **单文件应急**：`备份\rom_b25422107\` 内即原始文件，手动复制回去即可（SHA256SUMS.txt 可校验）。
- 注意：restore 会拒绝跨 buildid 还原（防内容回退），此时用第 2 级。

## 4. 更新随动流程（游戏每次更新后）

覆盖是**内容推导**的（zh 非空则 en:=zh），所以随动只需重放：

```
游戏更新后 → python 工具\zh_overwrite.py status
  ├─ 状态=已覆盖（补丁没动语言文件）→ 无需操作
  └─ 状态=原始（补丁重写了 TSV）→ python 工具\zh_overwrite.py apply
        （自动备份新版本原始文件到 备份\rom_b<新buildid>\，再覆盖；
          官方新增行若已带 zh 自动覆盖，尚未翻译的行保持英文——正好可当作官方新内容清单）
```

- 验证文件完整性后同理：status 显示"原始"→ 重跑 apply。
- 字体若被更新还原，apply 会一并重换（幂等）。
- 每个新 buildid 的原始备份自动留存，随时可精确回退该版本。

## 5. 注意事项与风险

- **en 列语义**：en 列今后既是显示文本也是回退源（全中文）。与 [润色\校对底表.csv](润色/) 的对照关系：底表 en 列是**原始英文**（基线导出），后续润色修改落盘时写 en 列（本模式下"我们想要的中文"就放 en）。
- **多人模式**：语言表纯本地显示，联机不受影响；他人看到的是他自己的语言。
- **官方启用中文后**：直接 `restore` + Steam 属性切简中即可切回官方通道；或继续本方案（内容相同）。
- **向官方反馈**时注意：本机当前文件已被修改，报 bug 前先 restore 或说明（引用行 id 即可，[03 发布指南](03_发布指南_创意工坊与GitHub.md) §4 口径不变）。
