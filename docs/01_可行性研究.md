# Anymaker 汉化可行性研究

**基准**：buildid 25422107 / 2026-09-21（所有游戏文件数字均为本日实测现查，非转抄）
**工程定位**（已确认）：校对+差异补丁型——以官方中文为基底做校对/润色，产出差异补丁(diff)，GitHub 发布术语表+补丁+本地安装脚本，向官方回馈勘误；创意工坊待官方开放语言类物品后跟进。
**结论先行**：❶ 官方中文已内置且覆盖率≈100%，本工程性质是"校对"而非"从无到有翻译"；❷ 游戏无外部语言加载口，改文本只能文件替换；❸ 创意工坊接口现状只支持载具蓝图，**语言文件现阶段无法上工坊**；❹ GitHub 发布完全可行（diff-only 原则规避版权灰区）。

## 2. 事实基线（全部实测于 2026-09-21，buildid 25422107）

### 2.1 语言文件清单与结构

位置：`<AM_GAME>\rom\`（5 文件，共 3,691,962 字节 / 1956 数据行）：

| 文件 | 内容 | 数据行 | 列数 |
|---|---|---|---|
| languages.tsv | UI 通用（按钮/设置/视觉脚本节点等） | 723 | 32 |
| languages_components.tsv | 载具组件名与描述 | 598 | 32 |
| languages_items.tsv | 物品名与描述 | 371 | 32 |
| languages_journal.tsv | 日记/剧情长文本 | 137 | 35 |
| languages_manual.tsv | 游戏内手册 | 127 | 32 |

- 通用 32 列 = `id` + `context` + 30 个语言列（en fr de es ja pt ru **zh** bg **zh-TW** cs da nl fi el hu id it ko ms no pl pt-PT ro es-419 sv th tr uk vi）；journal 在 `context` 后多 `dungeon`/`chapter`/`filter` 3 列共 35 列。
  （注：`数据库\04` §8 原记"29 语列"系漏计，实测为 30 语列，已在 04 册同步修正。）
- 编码：UTF-8 **无 BOM**；行尾 **CRLF**；单元格内换行为字面 `\n` 两字符转义（journal 单行最长逾万字符）。
- 键列 `id` 与 `rom\data\*.json` 定义表的 key 对应（如 `overalls` → items 表）；**待译文本 100% 集中在这 5 个 TSV，数据 JSON 无内嵌待译文本**（rom\data 内 locale/language/translation 关键词零命中，实测）。

### 2.2 zh / zh-TW 覆盖率实测（2026-09-21 现查）

| 文件 | 数据行 | zh 空 | zh-TW 空 | en 空 | zh==en |
|---|---|---|---|---|---|
| languages.tsv | 723 | 3 | 3 | 3 | 14 |
| languages_components.tsv | 598 | 0 | 0 | 0 | 0 |
| languages_items.tsv | 371 | 0 | 0 | 0 | 1 |
| languages_journal.tsv | 137 | 0 | 0 | 0 | 0 |
| languages_manual.tsv | 127 | 0 | 0 | 0 | 0 |

- 3 个 zh 空值行（`unused`、`control_hint_page_left/right`）英文列同为空，属占位行；zh==en 的 15 行中 2 行即上述空行，其余 13 行均为合理技术缩写（`h`/`m`/`s`、FXAA、SSAO、UI、`abs/floor/ceil/round/sqrt ###`、SMG A3T）。
- **即：有英文文本的行，官方中文覆盖率 100%**；zh-TW 同样完整。
- 译文质量抽样（非机翻占位）：`overalls → 工作服`、`engine → 发动机`、`gearbox → 变速箱`、`button_new_game → 新游戏`、journal 整段中文叙事（"埃尔林回来了，人不对劲。他说是着凉了……"）、manual（"现代生存指南"）。

### 2.3 字体

`rom\fonts\` 6 个 Noto Sans TTF：regular 646,160 / **sc（简中）10,595,948** / **tc（繁中）7,149,196** / jp 5,766,900 / kr 6,224,884 / thai 47,788 字节。中文字形资源随包附带，汉化**零字体工程量**。gcl 另有 `localization.get_script_font(e_localization_language)`（按语言选字体）与字形动态收集/图集重建符号（`_build_unique_characters`/`rebuild_glyphs`）——字形集从文本表动态生成，新增字符理论上随文本进表即可（符号证据）。

### 2.4 加载机制与语言选择（符号证据，非运行时结论）

- `localization.load_tables()` **无参数**：固定路径加载 rom 下 5 个 TSV（5 个文件名与全局表 `g_localization*` 一一对应存在于 gcl）；配套 `localization.load/save(file.path)` 带 `_encode/_decode_to_save_format`，语义服务于存档内唯一字符集序列化。
- **未发现**任何 override/外部语言目录/mod 加载符号（"mod" 符号 3 处全为视觉脚本取模运算假阳性，实测）。⇒ 改文本唯一途径是**替换 rom 下 TSV 文件**。
- 语言检测链：`application.steam.get_language` → `settings.general.get_default_language` → `e_localization_language` 枚举；TSV 内无"简体中文/繁體中文"等语言名 UI 串（实测 grep 零命中）⇒ 疑似**跟随 Steam 客户端语言、无游戏内切换页**（Stormworks 后来补了设置页语言切换，本作后续更新可能跟进——观察哨）。
- 每串有字形预算符号 `localization.get_budget_characters` ⇒ 译文过长存在截断/超预算风险（详见 [04_翻译与术语规范.md](04_翻译与术语规范.md) §5）。

### 2.5 创意工坊接口现状（符号证据 + 社区旁证）

- workshop 相关唯一符号 77 个，链路完整（`application.steam.create_workshop_item / update_workshop_item / delete_workshop_item / get_workshop_items_result / get_installed_items / begin_get_subscribed/published_items`），但**全部围绕载具设计**：`client_scene.vehicle_clipboard.read_from_workshop_file`、`frontend_ui_duplicate._build_ui_tab_duplicate_save_workshop`、目录前缀 `AnymakerWorkshopVehicle/`、预览图 `workshop_preview.png`（对应 `rom\placeholder_workshop_thumbnail.png`）。
- 无 mod SDK/文档/示例（全目录实测无 README/modding 说明）；`rom\data` 内 "workshop" 仅 manual.json 一句自然语言（复制工具可存设计到文件和工坊）。
- 社区侧（⚠ 第 4 级权威）：Workshop 发售日已可用，早期上传均为载具/基地/微控制器机械类。
- UGC 落盘：Steam 订阅运行时下载至 `steamapps\workshop\content\4435340\`，安装目录内无 mods/addons 文件夹（实测本机该目录不存在=未订阅任何物品）。

## 3. 与 Stormworks 汉化方式对照（只取方法论，不套技术假设）

| 维度 | Stormworks（前作实测记录） | Anymaker（本作实测） | 对本工程的含义 |
|---|---|---|---|
| 官方出口 | EA 前期 V0.5.20 加入"设置页语言切换 + **工坊语言文件物品类型**" | **无**：无语言物品类型、无 mod 通道 | 工坊发布现阶段不可行，列为观察哨 |
| 语言数据源 | 单文件 `language.tsv`，4 列（id/description/en/local） | 5 个 TSV、通用 32 列/journal 35 列、30 语列 | 结构更重，编辑纪律必须保列数/转义/CRLF |
| 官方中文 | 无官方中文，社区 BKN46 从零翻译 | **官方简繁已内置且≈100%** | 工程性质变为"校对/润色+勘误回馈" |
| 分发主通道 | 创意工坊订阅自动同步（工坊版常比 GitHub 新） | 现状只能本地文件替换；对外分发走 GitHub | GitHub 为源，本地安装脚本为分发形态 |
| 协作上游 | GitHub（BKN46/stormworks-translate-chn） | GitHub（本工程规划同构） | 方法论直接平移 |
| 下游资产 | 以 language.tsv 为唯一术语基准，脚本生成 8795 条对照表+SHA-256 新鲜度 | 以 5 TSV 官方 zh 列为基准（更优：官方译名直接可用） | 术语表生成脚本思路可抄（`<SW参照工作区>\汉化相关\脚本\build_glossary.py`） |
| 占位符 | `###` 数值 + `[$[action_xxx]]` 按键提示 | 仅 `###`（实测 2105 处，全在 languages.tsv；无 `[$[` 形态） | 翻译规范按本作实测裁剪 |

Stormworks 对本工程最宝贵的一条先例：**语言工坊支持是官方后补的**（V0.5.20），且同页补丁还在迭代字体西里尔支持——说明该厂有"先发游戏、后补本地化基础设施"的惯例，本作商店页语言列表现无中文但数据层中文已齐，正是同一模式的中间态。

## 4. 三条路线的取舍（决策记录）

| 路线 | 描述 | 判定 |
|---|---|---|
| **A. 校对+差异补丁型（选定）** | 官方中文为基底；GitHub 发布术语表+diff 补丁+本地安装脚本；勘误回馈官方 | ✅ 版权干净（不整包再分发）、EA 抗性强（diff 按新 buildid 重建）、与官方关系正向 |
| B. 纯术语资产型 | 只建中英术语表供工作区研究，不对外分发 | 弃：放弃了用户明确要的"发布"维度；可作为 A 的子集顺带完成 |
| C. 完整替换分发型 | 产出完整修改版 TSV 整包分发 | 弃：整包再分发游戏数据文件有版权灰区；EA 每次更新需重做全量文件；且官方中文已在，整包替换的收益/风险比最差 |

## 5. 双渠道发布判定（本研究的核心问题）

### 5.1 GitHub：✅ 可行（推荐主发布渠道）

- **仓库形态**（详见 [03_发布指南_创意工坊与GitHub.md](03_发布指南_创意工坊与GitHub.md)）：
  - `glossary/`：从 TSV 生成的中英术语表（id/en/zh/context），服务社区与 AI 翻译场景；
  - `patches/`：**仅含改动行**的差异文件（行 id + 新 zh 译文），不含任何完整游戏文件；
  - `tools/`：安装/卸载脚本——从玩家**本地**游戏文件读取原 TSV，套用 diff 重建修改版（备份→替换→可回滚）；校验脚本（列数/占位符/diff 范围检查）；
  - `docs/`：本工程文档的公开子集。
- **版权原则**：仓库不出现完整原始 TSV（含官方 en/zh 全列的整表属于游戏资产）；diff 只含"改了哪行哪个词"，属修改性表达的最小集合。BKN46 仓库整包分发 language.tsv 在 Stormworks 语境下是官方工坊机制的一部分，本作无此机制，不必也不应复制该形态。
- **发布节奏**：与 buildid 绑定打 tag（如 `v0.1-b25422107`），游戏更新后重生成 diff 再发新版。

### 5.2 创意工坊：❌ 现状不可行，转为观察哨

技术依据（§2.5）：工坊上传接口只有载具蓝图一条通路；游戏无语言文件加载口（工坊物品要生效必须有"游戏从订阅目录加载语言文件"的机制，符号层面不存在）。

**观察哨（满足任一即重评本节）**：
1. Steam 商店页语言列表出现中文（官方启用简/繁中的最直接信号）；
2. 新版 `game.gcl` 出现 language × workshop 交叉符号（如 `workshop_language` / 从 `installed_workshop_item_folder` 加载 TSV 的符号）；
3. 官方渠道（Discord/公告/工坊页）发布 mod/本地化支持文档；
4. 工坊物品类型扩展（社区出现非载具类物品且可正常加载）。

监控命令（下次游戏更新后跑）：
```bash
# buildid 核对（AGENTS.md §5）
grep -E "buildid" "<Steam库>/steamapps/appmanifest_4435340.acf"
# 工坊×语言交叉符号（必须 -a）
grep -aoE "[A-Za-z0-9_/.]*workshop[A-Za-z0-9_/.]*language[A-Za-z0-9_/.]*" "<AM_GAME>/bin/game.gcl" | sort -u
```

一旦开放：届时以**实测到的物品格式**为准重新打包（预案占位见 03 发布指南 §3），GitHub 仍保留为源码仓。

## 6. 风险与开放问题

### 6.1 V1（待办，优先级最高）：游戏内中文可达性实测

符号证据指向"语言跟随 Steam 客户端"，但未运行验证。**步骤**：Steam 客户端语言切简体中文 → 启动游戏 → 记录：主菜单/设置页是否中文、是否有语言选项、设置页语言枚举来自何处。结果记入本文件 §6.1 与 `数据库\06`。
- 若实测可直接中文：本工程的"本地补丁"仅为校对润色层，价值集中在勘误回馈与术语资产；
- 若实测**不可**达（如官方锁语言）：本地补丁的重要性上升，同时向官方请求启用中文（数据已齐，成本极低）。

> 启用路径的完整静态论证与 T1~T4 实测决策树见 [06_启用官方中文路径论证.md](06_启用官方中文路径论证.md)（2026-09-22 补充：settings.json 无语言字段已排除；Steam per-app 语言 blob 机制已本机验证；工具脚本已备于 工具\）。T3 观察项与本 V1 合并执行。

### 6.2 其余风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| EA 更新漂移 | TSV 行变动使 diff 失配 | 基线+SHA-256 锚定（[基线\基线说明.md](基线/基线说明.md)）；新 buildid 先 diff 官方改动再重放校对 |
| CRLF/`\n` 转义被编辑器破坏 | 文件不可加载或文本错乱 | 编辑纪律与校验清单（02 指南 §4）；禁止 Excel 类工具直接编辑（会重写引号/编码） |
| 译文超字形预算 | UI 截断（`get_budget_characters` 符号线索） | 翻译规范长度意识条款；上线前游戏内目检 |
| 官方更新覆盖官方 zh 列 | 官方改译与社区校对冲突 | diff 工具按行 id 三方对比（官方新版/官方基线/社区校对） |
| 版权灰区 | 整包分发风险 | 已定 diff-only 原则（§5.1），仓库审查清单在 03 指南 |

## 7. 结论

汉化**技术上可行且成本低**（明文 TSV+随包中文字体+官方中文基底），**分发上 GitHub 可行、创意工坊现阶段无门**。工程按"校对+差异补丁型"推进：先完成 V1 实测与术语表（衔接 `数据库\06` P0），校对产出以 diff 形态经 GitHub 发布，勘误同步回馈官方；工坊通道保持观察，开放后跟进。
