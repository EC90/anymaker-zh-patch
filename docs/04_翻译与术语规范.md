# 翻译与术语规范（Anymaker 校对+润色用）

适用对象：本工程全部 zh 列改动。基准 buildid 25422107。上位文档：[02_工作流程指南.md](02_工作流程指南.md)（格式硬约束）、[01_可行性研究.md](01_可行性研究.md)（背景）。

## 1. 术语来源优先级

| 优先级 | 来源 | 用法 |
|---|---|---|
| 1 | `languages_*.tsv` 官方 zh 列（基线） | **默认基底**：官方译名即基准，不改不算错 |
| 2 | 本工程 `术语\` 术语表（从基线生成） | 一致性检查基准；同一 en 概念多表出现时统一 |
| 3 | `<SW参照工作区>\汉化相关\` 术语基准（8795 条） | 仅参考：同厂前作概念传承（机械/生存类词汇），不直接搬 |
| 4 | anymaker.wiki 四语版（⚠ 第 4 级权威） | 仅旁证，不作为改动依据 |

**与官方译名不一致 = 勘误候选，不是直接改**：先进 `校对\` 记录表（附理由与证据），确认是官方错误才进 diff（见 03 指南 §4 回馈流程）。

## 2. 占位符纪律（实测形态，全部来自 2026-09-21 基线普查）

- **唯一占位符形态：`###`**（数值占位）。`languages.tsv` 内 2105 处，其余 4 表 0 处。示例：`binding_negative` en=`### NEGATIVE` zh=`### 负`；`rebind_is_bound_to` en=`### is bound to ###` zh=`### 已绑定到 ###`。
- **未发现** Stormworks 式 `[$[action_xxx]]` 按键提示占位、`%s`/`%d`/`{0}` 风格（全表 grep 实测零命中）——不要凭前作经验脑补占位符。
- 硬规则：改动行的 `###` **个数必须与 en 列相同**；语序调整时占位符随语义移动（"A is bound to B"→"B 已绑定到 A"时 `###` 对调是合法的）。
- 若未来基线普查发现新占位符形态，先更新本节再动笔。

## 3. 风格规范

1. **简体规范用字**（本项目只动 zh 列；zh-TW 官方已有且完整，原则上不动）。
2. 标点：句内全角标点；术语缩写/型号（FXAA、SSAO、SMG A3T）保持半角原样——基线 zh==en 的 13 行技术缩写即官方口径，勿"翻译"它们。
3. 数字/单位：跟随 en 列数值；单位词优先官方已有译法（`h/m/s` 官方保留原文，勿改为"时/分/秒"）。
4. 语气：UI 短语祈使/名词化（与官方 `button_new_game→新游戏` 风格一致）；journal/manual 叙事体保持官方文学语感（基线抽样显示官方叙事翻译质量高，改动须有明确理由）。
5. 组件/物品名与 `数据库\04` 定义表联动：改名会影响玩家按名字找物品，默认保持官方；确需改时术语表与 CHANGELOG 双更新。

## 4. 校对重点清单（按价值排序的排查方向）

1. `context` 列给的语境 vs zh 译文是否跑偏（context 是官方翻译提示，基线自带）；
2. 同一 en 多译 / 同一 zh 多源（一致性，用术语表脚本查）；
3. 机翻痕迹：生硬直译、漏译否定词、语序欧化；
4. UI 长度敏感区：按钮/标签类短串优先目检（§5 预算风险）；
5. `###` 空格规范：官方 zh 里 `###` 与中文之间保留空格（如 `### 负`），新改动保持同风格。

## 5. 长度预算意识

gcl 存在 `localization.get_budget_characters`（每串字形预算）符号——**符号证据，非运行时结论**，但按"译文可能被截断"对待：zh 明显长于 en 的改动（如 >1.5×）标记"待游戏内目检"；按钮类宁可精简。字形集按文本表动态收集（`_build_unique_characters` 符号），生僻字有渲染风险时优先常用字。

## 6. 工作产出的衔接

## 7. 第二轮润色术语表（2026-09-24 定稿，v1.3.0 生效）

网络语料检索 + Stormworks 惯例 + 现实规格比对后的裁定。改动入口：`工具\第二轮润色生成.py`（裁定数据内嵌，改后重跑再打包）。

### 7.1 弹药与武器（依据：多来源语料一致）

| 对象 | 裁定 | 依据 |
|---|---|---|
| 供弹 belt（弹药语境） | **弹链**（弹链面/弹链段/封闭式弹链段）；传动皮带语境的"皮带工具"保留 | 中文军语：金属链节供弹具=弹链（维基/军媒一致）；官方名表已用弹链、描述混译"皮带"属 LLM 残留 |
| 爆炸弹药/爆炸弹药 | **高爆弹** | 子弹级 HE 通行译法（杀爆弹为解放军炮弹语感，不用于枪弹） |
| 口径小数点 | 描述列 `556→5.56`、`762→7.62`、`308→.308`、`357→.357`、`45→.45`、`50→.50`（名表原本带点，描述被 LLM 丢点） | 出版规范：口径×壳长紧贴（5.56×45mm） |
| 乘号 | `×`（U+00D7）：`40 365mm→40×365mm`、`120x570mm→120×570mm`、瞄具 `5-25x56→5-25×56` | 维基/军媒一律 ×；官方"40 365mm"空格代乘号属错误 |
| 缩写 | GPMG/LMG/PDW/GMG/kWh 保留不动（用户自管） | 用户指令 |
| 武器代号（Rifle 107 类） | 高置信原型命名+半角括号英文原名（格洛克17手枪（G17 Pistol））；低置信→语义名+括号原名，进 [武器原型标注表](润色/武器原型标注表.md) 待用户标注 | mesh 三视图渲染（`工具\渲染武器mesh.mjs`）+全长毫米比对，多支与现实型号毫米级吻合 |
| 数据通道名（recording/signal/is_connected 等） | 保留英文 + `「」`括注 | 微控制器脚本实名引用（数据库\10 册接口表），不可译 |

### 7.2 管件（依据：GB/T 12459 管件体系 + SW 惯例）

| en | 裁定 | 说明 |
|---|---|---|
| tee / cross | **(T型) / (X型)**（SW 型号注记；正文提及用三通/四通） | SW：Pipe T-Piece→管道(T型) |
| straight / angle | **(I型) / (L型)** | SW 同 |
| reducer | **异径管(小→大)** | GB 规范名；官方"减压阀"为误译（reducer=变径管件，非泄压阀） |

| 阀门 | 截止阀(straight)/三通阀(t) | GB 用语 |

### 7.3 命名区分注记（141 组重名，~574 条改名）

- **SW 型号注记**：形状 `(I型)(L型)(T型)(X型)`、尺寸 `(小)(中)(大)`、格数 `(8x14)`、数值 `(0.33m)(90W)(4kWh)`；
- 纯外观变体无任何线索 → `(A)(B)(C)`；
- 英文括号仅兜底（无线索时）；武器代号类除外（见 7.1）；
- 发动机族按布局：直列/V型/水平对置；负重轮/链轮按半径；按钮/指示灯按 id 外观词。

### 7.4 描述文本

- ~~换行：≥60 字按句界插字面 `\n`~~ **已撤销（2026-09-24 游戏实测）**：物品 tooltip 渲染器把字面 `\n` 当**文本**显示（可见反斜杠+n），journal 表的 `\n` 换行约定**不适用于描述 tooltip**——两处渲染路径不同。描述保持单句流，不做手工分段；换行观感问题只能等官方 tooltip 排版改进或另行方案。
- 分号：英文分号句式直译残留的 `；`（61 处）→ `。` 保留有效。
- **数字单位紧贴（v1.3.2）**：数字与单位之间不留空格（`6rps`/`29.4kPa`/`850m/s`/`0.25L`）——tooltip 硬换行会把行尾空格当断点，紧贴可防单位被拆到下一行；与 SW 惯例一致。
- **武器名不加英文括注（v1.3.2）**：原型名（AK-107/HK416/AWP/M249/FN MAG…）本身可直接检索，括注徒增长度；统一风格为 `原型+中文类型词(+注记)`，配件跟随枪名。
- 双通道改描述：`desc` 词典类型写描述表 en/zh，经 `official_desc_map` 自动流入 JSON description。
