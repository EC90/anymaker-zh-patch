# 润色与打包指南（汉化包工作流）

**适用阶段**：游戏内汉化已生效（08 册严格模式），进入"持续润色 + 打包分发"阶段。基准 buildid 25436400 / 2026-09-22；v1.2.0 双路线改造于 25501161 / 2026-09-24。

## 1. 润色循环（改词即生效）

**唯一入口文件：[润色\润色词典.csv](润色/润色词典.csv)**，三列：`类型,键,中文`

| 类型 | 键 | 作用域 | 生效方式 |
|---|---|---|---|
| `gcl` | 界面英文原文（精确匹配，含大小写/###占位符） | gcl 内嵌串替换（最高优先级，覆盖自动/紧凑层） | `python 工具\patch_gcl_strings.py apply` |
| `name` | 定义表条目 id（如 `black_bear`） | JSON name 汉化（优先于 TSV 映射/内置生物表） | `python 工具\json_name_zh.py apply` |
| `tsv` | 语言表行 id（如 `manual_1`） | 语言表 en/zh 双列同改（无长度限制） | `python 工具\zh_overwrite.py apply`（玩家侧 v1.2.0 起生效） |

约束与提示：
- gcl 通道受**等长字节替换**限制：中文字节数（=字数×3）不得超过原英文字节数；超出会自动跳过并计入 status 报告。
- 想系统排查可润色项：跑 `patch_gcl_strings.py status`，它会重建 [润色\超长待译.csv](润色/)（当前 146 条：官方译超预算待短译 + 5 字节短词/4 字节单词[放弃区：单字中文观感差]）。
- name / tsv 通道无长度限制。
- 三类词条**只作用于润色后路线**；官方汉化文本路线忽略整个词典（见 §2）。
- 示例行见词典文件头两行（`gcl,Drag Person,拖人` / `name,black_bear,黑熊`）。

## 2. 安装路线（官方 / 润色后，v1.2.0 起）

安装器把"汉化"拆成两条路线，菜单 1 先问路线，也可 `install [official|polished]` 直接指定。

| 安装层 | 官方汉化文本路线 (`official`) | 润色后路线 (`polished`，默认) |
|---|---|---|
| ① TSV `en := zh`（官方 zh 列） | ✅ | ✅ |
| ① TSV 润色覆盖（词典 `tsv` 词条，en/zh 双改） | ❌ | ✅ |
| ② 字体 SC 覆盖拉丁槽 | ✅（非文本层，无此步中文不显示） | ✅ |
| ③ JSON 组件/物品 `name`（官方 zh 列） | ✅ | ✅ |
| ③ JSON 描述（官方新增描述表 zh） | ✅ | ✅（无描述表时退回内置 `DESCS`） |
| ③ JSON 生物/僵尸 `name`（社区 `CREATURE_ZH`） | ❌ 保持英文 | ✅ |
| ③ JSON `name` 润色覆盖（词典 `name`） | ❌ | ✅ |
| ④ gcl 官方对照替换 | ✅ | ✅ |
| ④ gcl `MANUAL`/`COMPACT`/词典 `gcl` 覆盖 | ❌ | ✅ |

**语义与实现要点**：

- 「官方汉化文本路线」严格零社区文本：不写入 308 条界面短译（MANUAL 72 + COMPACT 236）、46 条生物僵尸译名、18 条润色词典条目。代价是残留英文明显更多（F7 面板、5 字节内超短词、生物与僵尸名、旧版游戏的描述文本），这是路线定义本身的结果，菜单与完成后提示均已如实标注。
- **路线切换自动先还原再重装**：`_do_install` 比对 `安装状态.json` 的 `route`，不同则先调 `_restore_from_backup()`（与 uninstall 同一函数）再按新路线装，因此不会叠加残留。备份缺失时按 uninstall 同策略报错并指向 Steam 验证完整性。
- **实测差异（沙盒 25501161）**：官方路线 gcl 替换 361 条、超长跳过 298；润色后路线替换 625 条、跳过 106。差值即社区层贡献。
- `install` 省略参数时：有控制台 → `choose_route()` 询问（回车 = 上次路线）；无控制台（agent/管道）→ 默认 `polished`，不阻塞自动化。
- 顺带补齐了**词典 `tsv` 通道在分发侧的落地**（此前只有工程侧 `zh_overwrite.py` 实现，安装器只消费 `gcl`/`name`，README 却已向共建者承诺——属死条目）。

## 3. 打包流程

`python 工具\打包汉化包.py` 一键完成：
1. **生成 [汉化包\安装汉化.py](../汉化包/)**——自包含整合安装器（词典从 工具\ 两脚本实时导入内嵌，始终同源）：
   - 自动定位 Steam 库（注册表 SteamPath + libraryfolders.vdf，无需配置路径）；
   - `install [official|polished]`：①TSV en:=zh ②字体 ③JSON name/描述 ④gcl 严格替换（含长度前缀池签名校验），四步均按 §2 路线表分层；自备份到安装包旁 `备份_<buildid>\` 与 `备份_tsv\`；幂等，游戏更新后重跑即可；
   - `status`（打印当前路线）/ `uninstall`（按备份完整还原；路线切换复用同一还原函数）；
   - **版权干净**：翻译对在玩家本机从其游戏文件 zh 列推导，包内只有脚本与人工短译词（zip 仅 ~12KB，零游戏文本）——比 03 发布指南的 diff-only 原则更彻底。
   - ⚠ 安装器源码由本脚本的 `TEMPLATE` 生成：**改安装器必须改 TEMPLATE**，直接改 `汉化包\安装汉化.py` 会在下次打包时被覆盖。
2. 复制 `润色词典.csv`（润色随包分发，玩家也能改词）。
3. 生成 `使用说明.md` 并压 zip 到 `补丁\Anymaker简中汉化包_b<buildid>_<日期>.zip`。
4. 已测试 buildid 记录在安装器 `KNOWN_BUILDS`（25422107/25436400/25480554）；新版本按内容推导兼容，异常先 uninstall。

## 3.1 双路线验证（沙盒）

`python 工具\测试双路线.py`：把游戏 7 语言表/字体/4 JSON/gcl 复制到 `测试沙盒\`，排成伪造 Steam 库，只替换注册表 SteamPath 查询，使安装器走**未修改的 `find_game()` 路径**；真实游戏目录全程零写入。覆盖六组场景 41 项断言：官方路线零社区文本（TSV zh 列逐字节比对纯净副本）、切到润色后路线、幂等（gcl 哈希一致）、切回官方（痕迹清除，证明"先还原再重装"）、卸载 SHA-256 全等、CLI 与菜单入口（含非法参数退出码 2、非交互默认）。

## 4. 发布建议（衔接 03 发布指南）

- GitHub：仓库放本包三件套 + 工具源码 + 润色词典；release 按 buildid 打 tag。
- 任何渠道分发 zip 即可；玩家只需 Python 3.8+。
- 官方一旦在 Steam 语言列表启用简中：uninstall 后直接属性切中文（数据同源，体验更佳），本包退役为"字体/短词补差"可选件。

### v1.3.1 修订（2026-09-24 深夜，用户实测反馈）

1. **撤销描述 `\n` 分段**（66 条）：游戏实测物品 tooltip 把字面 `\n` 当**文本**显示（journal 表的换行约定不适用于 tooltip，两处渲染路径不同）——04 册 §7.4 已改记此结论。描述改写降至 38 条（纯术语替换）。
2. **武器标注落地**：用户填毕 [武器原型标注表](../润色/武器原型标注表.md) 16 件——AK-107/L85A3/HK416×2/Kar98k/AWP/M1911 MEU(SOC)/AUG A3 M1·M2/M249/FN MAG/Stevens 94/M870 Express×2/博福斯 L/70/RH120；其中 **M249 与 FN MAG 覆盖了此前"保留缩写名"的决定**。

### v1.3.2 修订（2026-09-25 凌晨，用户反馈"名太长 + 换行生硬"）

1. **武器名去英文括注**（用户实测括注使名字过长）：`AK-107突击步枪（Assault Rifle 107）`→`AK-107突击步枪`、`S&W686左轮手枪(2.5寸管)（Revolver）`→`S&W686左轮(2.5寸)`、`M870 Express泵动霰弹枪（Pump Action Shotgun）`→`M870 Express泵动霰弹枪`；原型名本身可直接检索，括注收益低于长度成本。
