# 残留英文治理（第二轮：en:=zh 之后的补充汉化）

**背景**：07 册的直接覆盖（en:=zh + 字体）后，用户实测反馈"游戏内选项和一些条目依然为英文"。本轮排查出全部残留英文源，按同一备份规矩治理。**基准 buildid 25422107 / 2026-09-22。**

## 1. 残留源排查结论（全部现查）

| 残留源 | 结论 | 处置 |
|---|---|---|
| rom 根目录其它文件 | 只有 5 TSV + fonts/data 等，无其它文本文件 | 排除 |
| journal 的 dungeon/chapter/filter 三列 | 实为数字 id 与技术标签（house/secure/hospital…），非显示文本 | 排除 |
| 数据 JSON 的 name 字段 | **组件(598)/物品(371)/生物(40)/僵尸(6) 四表 name 为英文显示名** → "一些条目"的来源 | ✅ 已译（1014 条） |
| tile/junction/dungeon_tile/prop 的 name | 是引用键（`definition_name` 等按名引用），**不能译** | 保持不动 |
| game.gcl 内嵌字符串 | 提取 291 个疑似 UI 串（扣除 TSV 已有词条后），其中含 Bloom Intensity/Camera Shake/Damage Vignette 等**硬编码选项标签** → "选项"的来源 | ✅ 58 条人工定稿词典已替换；其余 ~233 条为 dev/debug 面板串，默认不译 |
| game.exe 内嵌字符串 | 仅 libc++ 错误串，无 UI 文本 | 排除 |

判定依据：TSV 选项词条本身已翻译（如 `options_graphics_bloom` zh 列存在）——用户看到的英文选项必来自 TSV 之外；gcl 候选串清单可由 `patch_gcl_strings.py` 的提取逻辑复现（291 个，多为 F7 调试面板标签）。

## 2. 执行记录（2026-09-22）

### 2.1 JSON name 汉化（[工具\json_name_zh.py](工具/json_name_zh.py)）

- 组件/物品：按 id 从游戏**当前** TSV 的 zh 列取官方译名（随官方更新自适配）；
- 生物/僵尸：TSV 不覆盖，内置人工定稿表（黑熊/白头海雕/北美负鼠/驼鹿/灰熊/北极熊/变异僵尸…全 46 条）；
- 结果：`vehicle_component_definitions` 598 条、`inventory_definitions` 370 条（1 条本就中文）、`creature_definitions` 40 条、`zombie_definitions` 6 条，共 **1014 条 name 改写**；重序列化为 UTF-8 原缩进 JSON，重新解析校验全部有效、条目数不变。
- 抽验：`engine→发动机`、`overalls→工作服`、`black_bear→黑熊`、`zombie_tank→变异僵尸` ✅

### 2.2 gcl 等长字符串替换（[工具\patch_gcl_strings.py](工具/patch_gcl_strings.py)）

- **结构安全论证**：gcl 常量池字符串 NUL 结尾（实测前导/后继字节证据）；替换 = 原英文字节段 → 中文 UTF-8 + NUL 填充，**总字节长度严格不变**（无偏移位移），C 串语义下尾部 NUL 即终止符。匹配点前后字节不得为字母数字（防子串误伤）；译文超长自动跳过。
- 词典 58 条（高级图形/相机/天气/常用 UI：泛光强度、镜头震动、伤害暗角、阴影级联、主光/天光/背光、昼夜、云量/降雨/风力/气温、颜色面板、第一人称、平滑鼠标输入……全表见脚本 DICT）。
- 结果：**57 条替换成功**（Step Physics 2 处）；1 条跳过——"Orientation Smoothing Factor"因更短的"朝向平滑"已按前缀替换，其尾部" Factor"被 NUL 截断（C 串语义下不可见，无碍）。
- 复验：`game.gcl` 大小前后一致（81,576,416B）；`Bloom Intensity` 残留 0；`泛光强度`/`镜头震动`/`阴影纹素密度` 各命中 1 ✅

### 2.3 备份与还原升级

- 备份目录 `备份\rom_b25422107\` 新增 4 个 JSON 原件 + `game.gcl` 原件（81MB），SHA256SUMS.txt 已补全 11 项指纹。

## 4. 风险与应急预案

- **gcl 字节码替换**是本工程唯一的二进制改动：等长+边界校验下结构安全（§2.2），但 EA 字节码格式无官方保证。**若游戏启动崩溃或行为异常**：`python 工具\zh_overwrite.py restore` 整体还原，或 Steam"验证文件完整性"，然后把崩溃现象记录到本册 §5 再评估。
- gcl 内其余 ~233 个 dev/debug 面板串（F7 调试菜单、编辑器工具标签）默认不译——需要时向脚本 DICT 增补词条重跑即可。
- JSON name 若被某个未知 UI 当作匹配键使用（静态无证据），表现会是该条目功能失效——同上先 restore 再报告。

## 6. 根因分析（2026-09-22 深夜更新，重要认知修正）

用户截图（暂停菜单全英文）+ 现场取证推翻了 §1 的部分假设：

1. **游戏在 00:56 被 Steam 自动更新到 buildid 25436400**（appmanifest 实证），新 gcl 覆盖了旧 gcl——我们第二轮的 57 条 gcl 补丁在用户测试前就被冲掉，从未被验证过。
2. 但更本质：**改动 TSV en 列（07 册方案①）对英文界面从来无效**。决定性证据：`Return to Game`/`GAME MENU`/`Save Game` 等菜单文本同时存在于 TSV 行与 gcl 内嵌（新旧 gcl 各命中 1 次，且 TSV 的 699 个 en 值恰好内嵌于 gcl）——**英文界面的显示源是 gcl 内嵌字符串常量，TSV 只为非英语语言列服务**（en 列是翻译管线参照，非运行时显示源）。这解释了为何 en:=zh 后菜单毫无变化。
3. 新旧 gcl 的本地化符号集完全一致、内嵌 UI 串数量不变（291→290）——更新没有改机制，只是重置了文件。

## 7. gcl 内嵌全量替换（现行根治方案，已执行）

[工具\patch_gcl_strings.py](工具/patch_gcl_strings.py) 升级为三层词典自动替换（对 buildid 25436400 的 gcl，原件已备份 `备份\rom_b25436400\game.gcl`）：

- **auto 层**：基线 TSV 的 en→zh 官方对照 1481 对（en 原文与内嵌串天然同源）；
- **manual 层**：72 条硬编码串（泛光强度/镜头震动等）+ 高频界面串；
- **compact 层**：官方译超字节预算时的紧凑短译（存档/读档/回到主菜单/菜单/开局/窗口化/左旋转/教程与脚本编辑器公式等 60+ 条）。
- **字节预算**：替换长度 = 英文字节数 + 串尾 NUL 后连续 0x00 可用量（至少留 1 个 0x00）；总文件大小严格不变（81,609,841B 实证），C 串语义安全。
- **结果（两轮合计）**：约 620 条内嵌串替换生效（含全部菜单/设置/按键核心：返回游戏、存档、读档、回到主菜单、选项、联机、反馈、按键重新绑定、泛光强度、菜单、开局……），差异字节 ~11,974，英文残留抽查归零（GAME MENU/New Game/Return to Game/Exit to Main Menu/Multiplayer/Bloom Intensity 均 x0）。
- **已知边界**：约 300 条译超预算暂留英文——多为 5 字节短词（MUSIC/MOUSE/ULTRA 等 2 字中文需 6B 放不下）与 dev/调试长尾；需要时按"紧凑层"办法向脚本加词重放。
- **幂等/随动**：游戏更新（gcl 还原）后重跑 `apply` 即全量重建（全量扫描约 3 分钟）。

**现行更新随动顺序**（游戏每次更新后）：

## 8. 事故与修复记录（2026-09-22 01:20，重要）

- **事故**：§7 首版全量补丁（810 处替换）导致游戏启动未响应。已即时从 `备份\rom_b25436400\game.gcl` 恢复（SHA 核验一致）。
- **根因（实锤）**：首版自动层未过滤纯小写词条，而 gcl 中存在 NUL 界定的**引擎功能性常量**——`string`×16、`text`×6、`integer`×3、`fractional`×3、`boolean`×2、`comment`×1、`whitespace`×1（geocode 引擎自身的类型/属性名，与语言表中同名词条撞车）。其中 `integer→整数`、`fractional→小数`、`comment→注释`、`whitespace→空格` 字节恰好放得下被替换，引擎启动即损坏挂起。零区吞食是次要风险（取证未抓到直接越界证据，但一并禁用）。
- **严格模式（现行默认，已重新执行）**三条新约束：
  1. 被替换串必须**前导 NUL**（只动独立常量池，不碰长度前缀结构或数据内嵌串）；
  2. 预算=英文字节数，**不吃任何后续零区**，原 NUL 一律保留；
  3. 自动层**排除纯小写 en**（manual/compact 词典为人工审定大小写混合词，不受此限）。
- **结果**：462+紧凑条目替换生效（差异字节 9,566，大小不变 81,609,841B）；复验 `string/integer/...` 功能常量计数与备份完全一致，GAME MENU/New Game 英文归零，返回游戏/存档/读档/回到主菜单/选项/联机/菜单/开局/按键重新绑定全部落地中文。
- **一键恢复**：游戏再异常时双击 [工具\恢复gcl.bat](工具/恢复gcl.bat)（自动结束游戏进程并还原 gcl）；全量恢复用 `zh_overwrite.py restore` 或 Steam 验证完整性。
- 待用户重测：启动 → 暂停菜单/设置/按键页应为大面积中文；个别 5 字节短词（MUSIC/MOUSE/ULTRA）与调试面板仍英文属预期边界。
